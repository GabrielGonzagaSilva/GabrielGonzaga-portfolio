One product, two contexts. The interface keeps the same decision logic while adapting density and hierarchy across desktop and mobile.

THE CHALLENGE

Numbers are easy to display. Making them useful enough to support a real decision is the harder product problem.

The problem

Many calculators ask for unfamiliar terms or return a number without showing where it came from. That leaves users with an answer but little confidence about what it means.

The opportunity

Design a product where calculation, explanation, comparison and the next decision belong to the same experience instead of becoming disconnected pages.

PRODUCT PRINCIPLES

Trust and clarity are part of the interface.

01

Simplicity first

Keep inputs understandable and show the essential result before secondary detail.

02

Transparent calculations

Expose intermediate values, assumptions and formulas so the result can be checked.

03

Privacy by default

No mandatory account. Calculations can run in the browser without unnecessary personal data collection.

04

Neutral outcomes

The product quantifies scenarios without turning an estimate into an individual recommendation.

PRODUCT ARCHITECTURE

One repeatable decision flow.

The system is organized around a progressive sequence. Tools remain independent, while the product connects related decisions without forcing users through a rigid funnel.

FLAGSHIP FLOW · CLT × PJ

Compare the package, not only the monthly salary.

CLT × PJ is a priority flow because the user is rarely comparing two equivalent monthly numbers. Salary, benefits, annual rights, taxes and PJ costs need to be translated into a comparable reference.

The product starts with familiar monthly inputs, calculates an equivalent PJ value and then exposes how that reference was constructed.

Key product decision: the tool supports the financial comparison but deliberately does not decide whether CLT or PJ is “better” for the user.

TRUST BY DESIGN

The explanation layer is part of the product.

01 / PROGRESSIVE DISCLOSURE

Result first

The essential answer appears before composition, assumptions, sources and secondary details.

02 / METHODOLOGY

Make the number checkable

Relevant tools expose a “how we got this result” layer with intermediate values and assumptions.

03 / SOURCES

Identify changing rules

When official or external rules are involved, the interface connects the calculation to its year, methodology and references.

04 / QUALITY

Protect the system from regression

Calculation changes are covered by automated regression, security and responsive checks before release.

DESIGN TAKEAWAY

A useful calculator is not the product. The product is the path from a question to a number the user can understand, verify and use.

That principle changed the architecture from a catalogue of isolated calculations into a decision-support system with reusable behavior, transparent methodology and connected journeys.
